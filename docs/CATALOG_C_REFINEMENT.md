# Catalog C Refinement (Grocery UX) — Navbar / Sorting / Filters

Дата: 2026-03-28  
Пакет: backlog `034`  
Цель: усилить сценарий “быстрый выбор” в `catalog-c` без смены концепции.

## 1) Что меняем в navbar

### Базовый принцип

Navbar в C-режиме не “для бренда”, а для скорости: поиск, отделы, корзина, быстрые статусы. Все вторичные ссылки убираем из первого экрана.

### Desktop / Tablet

Меняем на 2-уровневую, но компактную структуру:

- Уровень 1 (fixed):
  - `Search` (ширина максимум)
  - `Cart` (сумма + кол-во, один CTA)
  - `Account` (иконка/кнопка без текста)
- Уровень 2 (sticky, под поиском, высота 40–48px):
  - `Отделы` (категории) в виде горизонтального списка (scrollable tabs)
  - справа: быстрые “режимы” (только 2–3): `В наличии`, `Скидки`, `До X`

Что убираем из navbar в C:

- длинные меню “каталог/бренды/коллекции/блог” (они мешают скорости и не нужны в режиме супермаркета)
- “вдохновляющие” блоки, баннеры, промо-галереи

### Mobile

Меняем на “one-hand” header:

- Верх (fixed):
  - `Search` в 1 строку (крупный, с clear)
  - `Cart chip` справа: `N · сумма` (тап ведет в корзину)
- Под ним (sticky):
  - `Отделы` (scrollable tabs, 1 ряд)
  - optional: иконка `Фильтры` (если не помещается в control row)

Обязательное: в C все ключевые элементы должны быть доступны большим пальцем, не требовать точного тапа по маленьким иконкам.

## 2) Как меняем sorting

### Цель sorting в grocery

Sorting не “для исследования”, а для ускорения закупки. Поэтому:

- меньше опций
- самые важные сверху
- быстрый переключатель без экрана “настроек”

### Предлагаемая модель

1. Default: `Популярное` (или “Часто покупают”)  
   Логика: минимизируем принятие решений.
2. Quick переключатель (segmented, 3 пункта):
   - `Популярное`
   - `Цена`
   - `Скидки`

Раскрывающийся список “всё остальное” (bottom sheet / dropdown):

- `Рейтинг` (если реально влияет)
- `Новинки` (опционально)

Важно: в C sorting не должен “сбрасывать” прокрутку резко. При смене сортировки:

- сохраняем категорию/отдел
- аккуратно возвращаем пользователя к началу текущего отдела, а не к вершине всего каталога

## 3) Как меняем filters

### Философия

В C фильтры должны быть “не страшными” и быстрыми: 80% случаев закрывают быстрые toggles, а “тяжелые” фильтры прячутся в один drawer/sheet.

### Быстрые фильтры (всегда на виду)

Постоянные chips/toggles в control row:

- `В наличии`
- `Скидки`
- `Цена` (открывает мини-popover с пресетами + min/max)
- `4+` (рейтинг)

Цена (минимально):

- 3 пресета (например): `до X`, `X–Y`, `от Y`
- min/max поля внутри (но не на первом экране)

### Advanced filters (один экран, но строго)

Открывается через `Фильтры (N)` (drawer/bottom sheet):

- `Brand` (поиск внутри списка)
- `Availability` (дублируем, но не обязательно)
- `Rating`
- `Discount`
- `Seller` (если нужно B2B)
- `Lead time / доставка` (только если данные реально есть и понятны)

Обязательные правила sheet:

- `Применить` закреплено снизу
- `Сбросить` рядом, но вторично
- всегда видно, сколько товаров соответствует (или хотя бы “обновится список”)
- не делать 10+ секций по умолчанию: максимум 4–6, остальное скрывать (“ещё фильтры”)

### Фильтры не должны ломать fast-pick

Если фильтры активны, в results-списке надо показывать 1 строку “активные фильтры” (chips) и `Очистить`, но без “тяжелого” блока.

## 4) Mobile UX (усиливаем быстрый выбор)

### 4.1 Главное: непрерывный “список закупки”

- Результаты: плотный list-row (как в супермаркете), где цена и stepper всегда в одном месте.
- Stepper:
  - крупный
  - мгновенная обратная связь
  - не прячет цену

### 4.2 Sticky bottom bar

Для C на mobile обязательно:

- Bottom bar: `N товаров · сумма` + CTA `Оформить` (или `В корзину`)
- CTA всегда доступен, не требует скролла к верху

### 4.3 Быстрые изменения без лишних экранов

- Sort: segmented переключатель прямо в интерфейсе.
- Filters: chips всегда рядом с результатами, advanced filters только при необходимости.

### 4.4 Снижаем когнитивную нагрузку

- Уменьшаем “визуальный шум” в карточках:
  - рейтинг и отзывы показываем вторично
  - фото маленькое, но стабильное
  - главное: цена, наличие, stepper

## 5) Плюсы / минусы изменений

Плюсы:

- меньше кликов до добавления в корзину
- меньше “решений” (segmented сортировка, быстрые фильтры)
- лучше one-hand mobile UX
- проще повторная закупка: список, отделы, stepper, bottom summary

Минусы:

- меньше “витринности” и discovery-эффекта
- часть пользователей захочет больше параметров сравнения (их уводим в A/B режимы и PDP)
- нужно строго следить, чтобы быстрые chips не расползлись в хаос

## 6) Что обязательно должно остаться прежним (не трогаем)

Чтобы `catalog-c` оставался именно grocery “быстрый выбор”, сохраняем:

- максимальную плотность результатов (list-row, не “витрина”)
- `stepper qty` прямо в списке как главный CTA (не прячем за PDP)
- sticky bottom cart summary на mobile
- категорийный “переключатель отделов” рядом с поиском (tabs/scroll)
- минимум фильтров на первом экране, advanced filters в одном sheet
- строгую сетку и ритм 4/8px, без декоративности и сложных анимаций
