# Servio — 4 Desktop-Only Catalog Concepts (V1)

Дата: 2026-03-28  
Пакет: backlog `041`  
Ограничение: desktop-only. Не mobile-first. Не адаптация mobile.  
Ориентир: utilitarian commerce UX (быстро найти, сравнить, выбрать, купить).

## 0) Цель

С нуля предложить 4 разные desktop-only концепции каталога, которые отличаются:

- поведением пользователя
- плотностью информации
- способом выбора и добавления в корзину

При этом визуальная система одна (единая дизайн-система), без “креативных” паттернов.

## 1) Общая desktop-only дизайн-система (единая для всех 4 концепций)

### 1.1 Сетка, размеры, ритм

- Базовая единица: `4px`. Основной шаг: `8px`.
- Контейнер: `1280–1440px` (content max-width), с предсказуемыми gutter.
- Главная сетка каталога: `filters / results / side-utilities` в рамках одной страницы.
- Никаких “плавающих” отступов: все кратно 4px.

### 1.2 Типографика

Цель: быстро читать цену, название, наличие; не уставать от плотности.

- Title страницы: 24/28, weight 600.
- Подзаголовки секций: 16–18/24, weight 600.
- Текст карточек/строк: 13–14/18–20.
- Цена: 18–20/24, weight 700.
- Метаданные (бренд, SKU, наличие): 12/16, weight 400.

### 1.3 Цвет и акценты

- Светлая база, нейтральные поверхности.
- Один основной акцент для CTA “В корзину”.
- Скидка и старая цена: вторичный сигнал, читаемый, но не агрессивный.
- Наличие: текст + понятный индикатор, без reliance-only-on-color.

### 1.4 Компоненты (должны быть одинаковыми)

- Header: поиск, категории, корзина (badge + сумма), аккаунт.
- Toolbar: сортировка, view toggle (если есть), “Фильтры (N)”, “Сбросить”.
- Filters: фасеты, поиск по фасетам, clear/reset, apply (если нужно).
- Listing: стабильные слоты для фото, имени, цены, наличия, CTA.
- Add-to-cart: кнопка + переход в qty stepper.
- Compare/Favorites: только если не создают шум (см. “запреты”).
- States: loading (skeleton), empty, error, partial (нет части данных).

### 1.5 Desktop ergonomics

- Hover используется как ускоритель, но не как единственный способ.
- Клавиатура: таб-фокус, быстрый поиск, управление количеством (стрелки/enter) по возможности.
- Кликабельные цели не меньше 32px по высоте на desktop.

## 2) Категорически запрещено

- Mobile-паттерны как основа: bottom sheets, hamburger как главный вход, “липкие” нижние панели.
- Декоративные баннеры и визуальные эффекты без коммерческой функции.
- Сложные анимации и “переходы ради красоты”.
- Нестандартная навигация, требующая обучения.
- Переусложнение фильтров: 20+ секций без группировки и без поиска по фасетам.
- “Премиальный” тон: огромные отступы, пустые пространства, витринная “галерея” вместо закупки.
- Скрытые важные данные (цена/наличие) ради минимализма.

## 3) Концепция 1 — Classic Facets + Dense Grid (универсальная)

### 3.1 Идея

Классический marketplace desktop: фасеты слева, плотная сетка карточек, быстрый add-to-cart. Пользователь сравнивает визуально, но без “витринных” украшений.

### 3.2 Структура

- Header: поиск, категории, корзина, аккаунт.
- Breadcrumbs + заголовок категории/запроса.
- Toolbar: sort, chips активных фильтров, “Сбросить”, view toggle (grid/list).
- Main:
  - Left: Filters panel (фикс ширина, scroll внутри).
  - Center: Grid (4–6 колонок по ширине).
  - Right: опционально “Compare tray” или “Recently viewed” (только если не шумит).

### 3.3 Navbar / Header

- Search максимально широкий.
- Быстрые подсказки под поиском (suggestions) допускаются позже, но не обязаны в V1.
- Корзина всегда видима: count + сумма.

### 3.4 Фильтры

- Фасеты: цена, бренд, наличие, рейтинг, скидки, seller, delivery/lead-time (если релевантно).
- Поиск внутри фасета “бренд/категории”.
- “Сбросить” и счётчик выбранных фильтров.

### 3.5 Сортировка

- Популярное/Рекомендованное (default)
- Цена (asc/desc)
- Рейтинг
- Новинки

### 3.6 Карточка / листинг

- Карточка средней плотности, фиксированные слоты.
- CTA “В корзину” крупный; после добавления — stepper.
- Наличие и min order qty (если B2B) рядом с CTA.

### 3.7 Сценарий выбора товара

1. Пользователь уточняет выбор фасетами.
2. Сравнивает 2–5 карточек по цене/наличию/рейтингу.
3. Добавляет в корзину из листинга, PDP открывает только при сомнениях.

### 3.8 Отличия

- Самая универсальная, “как ожидают” на desktop.
- Упор на визуальное сравнение карточек, но без “витрины”.

### 3.9 Плюсы

- Понятно сразу, без обучения.
- Хорошо покрывает широкий ассортимент.
- Масштабируется по фасетам.

### 3.10 Минусы

- При закупке больших списков карточки могут быть менее эффективны, чем таблица.
- Compare может засорять, если дать слишком рано.

## 4) Концепция 2 — Procurement Table Mode (таблица закупки)

### 4.1 Идея

Каталог как “таблица закупки”: плотный табличный листинг с колонками, быстрым qty и bulk add. Максимум эффективности, минимум визуального шума.

### 4.2 Структура

- Header + breadcrumbs.
- Toolbar:
  - sort
  - quick filters (availability/discounts)
  - view = “Table” (основной режим)
  - bulk actions (добавить выделенное, очистить выделение)
- Main:
  - Left: Filters panel (можно compact).
  - Center: Table listing.
  - Optional top row: “Сравнение выделенных” (2–4 позиции) как табличное сравнение столбцами.

### 4.3 Navbar / Header

- Search + быстрый “Paste SKU list” (если B2B нужно) как вторичная функция.
- Корзина: count + сумма, всегда видима.

### 4.4 Фильтры

- Сокращаем список фасетов на первом экране.
- Сильный “Brand search” и price range.
- Availability как quick toggle.

### 4.5 Сортировка

- Популярное (default)
- Цена
- Наличие/lead-time (если есть)
- Discount

### 4.6 Карточка / листинг

Табличная строка:

- Колонки: фото мини, название, бренд, цена, скидка, наличие, qty, add.
- Qty control всегда видим в строке.
- Sticky header таблицы.

### 4.7 Сценарий выбора товара

1. Пользователь быстро фильтрует.
2. Скроллит таблицу, добавляет количества сразу.
3. Использует bulk add и быстрые корректировки qty.

### 4.8 Отличия

- Не “смотрю витрину”, а “закупаю списком”.
- Максимальная плотность и скорость.

### 4.9 Плюсы

- Лучший режим для больших корзин и B2B.
- Меньше скролла на товар, быстрее add-to-cart.

### 4.10 Минусы

- Меньше эмоционального discovery.
- Требует дисциплины в колонках, иначе станет перегруженной.

## 5) Концепция 3 — Master List + Detail Preview (двухпанельный выбор)

### 5.1 Идея

Список товаров слева/по центру, а справа — фиксированная панель предпросмотра выбранного товара (мини-PDP). Переходов меньше, выбор быстрее, сравнение “в голове” проще.

### 5.2 Структура

- Header + toolbar.
- Main:
  - Left: filters (можно компактнее).
  - Center: list (или grid 2–3 колонки), клик по товару меняет selection.
  - Right: preview panel:
    - фото побольше
    - цена, скидка
    - ключевые атрибуты (3–6)
    - наличие/lead-time
    - CTA add-to-cart + qty
    - ссылка “Открыть карточку”

### 5.3 Navbar / Header

- Search всегда visible.
- Preview panel не заменяет header, а ускоряет решение.

### 5.4 Фильтры

- Как в Concept 1, но можно скрыть “редкие” фасеты по умолчанию.

### 5.5 Сортировка

- Популярное (default)
- Цена
- Рейтинг
- Наличие (если критично)

### 5.6 Карточка / листинг

- В листинге карточка может быть компактнее (т.к. справа preview).
- В list-row можно убрать часть метаданных, чтобы снизить шум.

### 5.7 Сценарий выбора товара

1. Скроллит results, кликает по товарам.
2. Смотрит детали справа без ухода на PDP.
3. Добавляет выбранное и двигается дальше.

### 5.8 Отличия

- Уменьшает “скачки” между каталогом и PDP.
- Превращает выбор в последовательный поток.

### 5.9 Плюсы

- Быстрее принятие решения по сложным товарам.
- Меньше открытых вкладок и возвратов.

### 5.10 Минусы

- На узких ширинах потребует деградации (preview panel можно сворачивать).
- Риск перегрузить preview, если попытаться туда “всё”.

## 6) Концепция 4 — Shortlist-First + Compare Rail (выбор через отбор)

### 6.1 Идея

Пользователь не пытается “выбрать сразу”. Он собирает shortlist (3–10 товаров), затем выбирает через сравнение/отбор в боковой панели. Это помогает при сомнениях и похожих позициях.

### 6.2 Структура

- Header + toolbar.
- Main:
  - Left: filters.
  - Center: results (grid/list).
  - Right: shortlist rail:
    - выбранные товары (мини-строки)
    - быстрый compare view (таблица 2–4 товаров) по ключевым параметрам
    - CTA: “Добавить выбранное в корзину” (bulk)

### 6.3 Navbar / Header

- Search и корзина — как обычно.
- Shortlist rail не должен “съедать” ширину результата; на узких экранах сворачивается.

### 6.4 Фильтры

- Полные фасеты как в Concept 1.
- Дополнительно: “показывать только shortlist” как toggle.

### 6.5 Сортировка

- Популярное, Цена, Рейтинг.
- Опционально “Сначала shortlist” как режим, не как сортировка.

### 6.6 Карточка / листинг

- Карточка/строка получает secondary action “В shortlist”.
- Add-to-cart может быть только на shortlist rail (чтобы не дублировать решения), или в обоих местах (если не шумит).

### 6.7 Сценарий выбора товара

1. Быстро отмечает подходящие товары в shortlist.
2. Сравнивает shortlist по параметрам в rail.
3. Добавляет финальные позиции в корзину bulk.

### 6.8 Отличия

- Выбор через отбор и финальную валидацию.
- Уменьшает “ошибочные” покупки при близких товарах.

### 6.9 Плюсы

- Хорошо для категорий, где нужно сравнение.
- Ускоряет финальную покупку после shortlist.

### 6.10 Минусы

- Лишний шаг “сначала собрать”, если пользователь уже знает, что покупать.
- Нужна дисциплина, чтобы shortlist rail не стал мусорным.

- Делать реализацию “как есть” без декоративности.
- Только после этого думать о mobile (это отдельный пакет, не из desktop).
