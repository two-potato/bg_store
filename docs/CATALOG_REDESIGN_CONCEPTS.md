# Servio Catalog Redesign — 3 UX Concepts (A/B/C)

Дата: 2026-03-27  
Роль: UI/UX  
Ориентиры: Яндекс Маркет, grocery UX (Перекресток)  
Принцип: утилитарный коммерческий интерфейс для быстрого поиска, сравнения и покупки.  
Запрещено: премиальность, экспериментальный UI, декоративность без пользы, сложные анимации, нестандартная навигация.

## 0. Контекст и цель этапа

Мы делаем полный редизайн всего пользовательского продукта (home, catalog, PDP, cart, checkout, account и т.д.), но первый этап — только каталог в трех разных поведенческих моделях:

- `A /catalog-a` — классика маркетплейса (баланс “смотрю и сравниваю”).
- `B /catalog-b` — mobile-first (баланс “ищу и фильтрую большим пальцем”).
- `C /catalog-c` — быстрый выбор / супермаркет (баланс “беру сразу, без разглядывания”).

Важно: концепции должны отличаться поведением пользователя, плотностью информации и способом выбора. Визуальный стиль при этом один (единая дизайн-система).

## 1. Единая дизайн-система (общая для A/B/C и для будущих home/PDP/cart/checkout/account)

### 1.1 Сетка и ритм (строго)

- Базовая единица: `4px`.  
- Основные шаги: `8 / 12 / 16 / 24 / 32 / 40 / 48`.  
- Все отступы и размеры кратны `4px`. Никаких “на глаз”.

Контейнер и колонки:

- Desktop container: `1200–1280px` контентной ширины.
- Общий layout: header (fixed), затем content.
- Для каталога:
  - Desktop: `filters + results` (двухколоночная схема) или `results` с overlay фильтрами.
  - Tablet: фильтры уезжают в drawer.
  - Mobile: фильтры в bottom sheet, сортировка и быстрые фильтры в sticky-row.

### 1.2 Выравнивание и композиция

- Все карточки и блоки сидят на единой колонной сетке; одинаковые gutter.
- Результаты (список товаров) имеют предсказуемую высоту карточек и стабильные зоны:
  - верх: название/бренд
  - середина: price + discount + rating/availability
  - низ: CTA add-to-cart / quantity stepper
- Любое “прыгание” высот устраняется через ограничение строк, фиксированные слоты и skeleton.

### 1.3 Типографика (чисто, читаемо, без “дизайнерства”)

Цель: быстро читать цену и имя товара, не уставать.

- Base font: системный нейтральный sans (без премиальных шрифтов).
- Масштаб:
  - Page title: `24/28`, weight 600
  - Section title: `18/24`, weight 600
  - Card title: `14/18`, weight 500–600, 2 строки максимум
  - Meta: `12/16`, weight 400 (бренд, фасеты, наличие)
  - Price: `18/24` (desktop) и `16/20` (mobile), weight 700
  - Old price: `12/16`, strike, secondary
- Числа и цена визуально доминируют над декоративными текстами.

### 1.4 Цвет и контраст (светлая база, акцент на цене и CTA)

- Фон: светлый, нейтральный (без градиентов/плашек ради красоты).
- Поверхности: белые карточки или слегка тонированные (только для читаемости).
- Акценты:
  - CTA (добавить/купить): один основной акцентный цвет.
  - Скидка: отдельный сигнал (badge) без агрессии.
  - Наличие: нейтральный “в наличии/под заказ” + количественный сигнал.
- Контраст: достаточный для чтения при дневном свете, особенно на мобильном.

### 1.5 Компоненты и паттерны (строго и повторяемо)

Обязательные паттерны, одинаковые для A/B/C:

- Search: input + suggestions (позже), clear, voice/scan не добавляем на этом этапе.
- Categories: дерево или список, всегда доступный путь “сбросить/назад”.
- Filters:
  - Price range (min/max + быстрые пресеты)
  - Availability
  - Brand
  - Rating
  - Discount / promo
  - Seller (если B2B нужно)
  - Delivery/lead time (если критично)
- Sorting:
  - Popular / Recommended
  - Price asc/desc
  - Rating
  - New
- Product card:
  - Фото (1:1 или 4:3, стабильный слот)
  - Название + бренд
  - Price + old price + discount badge
  - Rating + count
  - Availability (в наличии/под заказ/нет)
  - CTA: `Add` или `Stepper` (если в корзине)
- Compare:
  - В каталоге: быстрый toggle (без отдельной “супер-страницы” на этапе 1)
  - В будущем: сравнение как buyer tool (но паттерн toggle закладываем сразу)
- States: loading skeleton, empty (нет товаров), error (API/сеть), partial (часть фильтров недоступна).

### 1.6 A11y и mobile ergonomics

- Все интерактивные элементы: min `44x44px` на mobile.
- Focus-visible обязателен, порядок табов логичный.
- Stepper qty: aria-label и клавиатурный контроль.
- Не полагаться только на цвет для скидок/статусов.

### 1.7 Как это переносится на весь продукт (следующие этапы)

Единый “коммерческий каркас”:

- Header: поиск, категории, “Корзина” с бейджем, аккаунт.
- Bottom sticky summary (на mobile): для cart/checkout и для концепции C.
- Card patterns и price/CTA hierarchy одинаковы в catalog/PDP/cart.
- One-source-of-truth для статусов: наличие, доставка/lead time, скидки, промо.

## 2. Концепция A — классика маркетплейса (баланс “сравнить и выбрать”)

### 2.1 Идея

Пользователь “смотрит витрину”, сравнивает предложения, фильтрует слева (desktop) и выбирает по цене/рейтингу/наличию. Максимальная предсказуемость.

### 2.2 Структура

Desktop:

- Header (sticky): Search, Categories, Cart, Account.
- Под header: breadcrumbs + заголовок категории/поиска.
- Row “Controls”: sort + view toggle (grid/list) + “Фильтры (N)” (на tablet).
- Main:
  - Left: filters panel (фикс ширина, скролл внутри)
  - Right: results
    - selected filters chips + clear all
    - grid карточек (3–5 колонок по ширине)
    - pagination или infinite scroll (предпочтительнее pagination для предсказуемости; можно гибрид: load more)

Mobile:

- Sticky row: sort + filters + quick chips.
- Results: grid 2 колонки или list (настройка).

### 2.3 Логика поведения пользователя

1. Вводит запрос или заходит в категорию.
2. Быстро корректирует результат через фильтры слева.
3. Смотрит карточки, сравнивает 2–3 товара.
4. Добавляет в корзину из каталога (без PDP для повторных покупок).
5. Для сомнений переходит в PDP.

### 2.4 Фильтры

- Полная “маркетплейсная” фасетная панель.
- Важно: фильтры не должны прыгать при выборе.
- Быстрые пресеты цены и “В наличии” сверху панели.
- Счетчик выбранных фильтров + clear.

### 2.5 Карточки

Карточка средней плотности:

- Фото, название, бренд.
- Price блок доминирует.
- Rating + reviews count.
- Availability (в наличии / под заказ) + lead time (если есть).
- CTA: `Добавить` -> `Stepper` после добавления.
- Secondary actions: compare toggle, favorite toggle (малые, но доступные).

### 2.6 Mobile UX

- Filters: bottom sheet с четкими секциями и кнопками `Применить / Сбросить`.
- Sticky cart badge.
- По умолчанию list view для читаемости, grid как опция.

### 2.7 Отличия

- Самый “универсальный” и привычный.
- Опора на левую фасетную панель (desktop) и классический поток сравнения.

### 2.8 Плюсы

- Понятно без обучения.
- Хорошо работает для широкого ассортимента.
- Удобно сравнивать.
- Хорошо переносится на B2B сценарии (много параметров).

### 2.9 Минусы

- Больше “взгляда и анализа”, медленнее “быстро купить”.
- На mobile легко перегрузить фильтрами, нужен строгий минимализм в sheet.

## 3. Концепция B — mobile-first (баланс “фильтрую и покупаю большим пальцем”)

### 3.1 Идея

Каталог строится вокруг мобильной эргономики: быстрые фильтры (chips), bottom sheet для сложных фильтров, результаты в list с “одним взглядом”, минимизация кликов до add-to-cart.

### 3.2 Структура

Mobile (основная):

- Header sticky:
  - Search (на весь ряд)
  - ниже: row с кнопками `Категории`, `Фильтры (N)`, `Сортировка`, `Вид`
- Quick chips (горизонтальный скролл):
  - `В наличии`, `Скидки`, `4+`, `До X`, `Бренд: ...` (после выбора)
- Results: list карточек (1 колонка)
- Sticky bottom: mini cart summary (кол-во + сумма) и CTA “Перейти в корзину”

Desktop:

- Тот же UI, но фильтры могут быть слева (по желанию), приоритет — единообразие поведения.

### 3.3 Логика поведения пользователя

1. Ищет/заходит в категорию.
2. Быстро включает 1–2 chips (в наличии/скидки/рейтинг).
3. Прокручивает ленту товаров, добавляет 3–10 позиций.
4. Переходит в корзину из sticky summary.

### 3.4 Фильтры

- Chips как “быстрые переключатели” (boolean/пресеты).
- Bottom sheet:
  - крупные контролы
  - сохранение промежуточного состояния
  - “применить” закреплено снизу
- При закрытии sheet всегда видно, сколько товаров отфильтровано.

### 3.5 Карточки

List-card высокой эффективности:

- Слева фото, справа:
  - Название (2 строки)
  - Price + discount
  - Rating
  - Availability
  - Stepper/CTA внизу справа, рядом “+” без мелких целей
- Упор на thumb reach: CTA всегда в одной зоне.

### 3.6 Mobile UX

- Sticky bottom cart summary — ключевой паттерн.
- Все действия доступны без “попаданий по мелким иконкам”.
- Минимум модалок; все изменения отражаются мгновенно.

### 3.7 Отличия

- Результаты как “лента покупок”.
- Controls нацелены на быстрые изменения и короткий цикл.

### 3.8 Плюсы

- Максимальная скорость на mobile.
- Меньше кликов, выше конверсия в add-to-cart.
- Удобно для повторных покупок.

### 3.9 Минусы

- Для глубокого сравнения параметров иногда не хватает “плотности”.
- Нужна аккуратная архитектура chips, чтобы не превратить их в хаос.

## 4. Концепция C — быстрый выбор / супермаркет (баланс “беру как в продуктовой ленте”)

### 4.1 Идея

Каталог как “список закупки”: максимальная плотность и скорость добавления, минимальные переходы в PDP. Пользователь выбирает быстро по цене/наличию и управляет количеством прямо в списке.

### 4.2 Структура

Mobile:

- Header: Search.
- Secondary sticky: category switcher (вертикальный список/горизонтальный таб-скролл).
- Results: компактный list-row (почти таблица):
  - фото мини
  - название 1–2 строки
  - цена крупно
  - stepper qty
  - наличие/ограничения мелко
- Sticky bottom: “В корзине: N / сумма” + CTA “Оформить”

Desktop:

- Можно держать results в “табличной” плотности (list), фильтры в drawer/панели.
- Важнее скорость выбора, чем красивые карточки.

### 4.3 Логика поведения пользователя

1. Быстро переключает категории (как отделы супермаркета).
2. Скроллит короткими порциями, добавляет количества.
3. Смотрит на bottom summary, завершает закупку.

### 4.4 Фильтры

- Минимальный набор в первом экране: `В наличии`, `Скидки`, `Цена`.
- Остальные фильтры доступны, но вторичны (drawer).
- Сортировка по умолчанию: “популярное/часто покупают”.

### 4.5 Карточки

Row-card максимальной плотности:

- Цена и stepper — главные элементы.
- Рейтинг/отзывы — вторичны (по желанию скрываем).
- Фото маленькое, чтобы не съедать список.
- Для B2B можно показать “мин. заказ / кратность” рядом со степпером.

### 4.6 Mobile UX

- Thumb reach: stepper и CTA закреплены в зоне нижней трети.
- Минимум “пустого воздуха” между рядами, но сохраняем читабельность (8px вертикальный ритм).

### 4.7 Отличия

- Максимальная скорость “добавить много”.
- Визуально похож на grocery list, но без декоративных элементов.

### 4.8 Плюсы

- Самый быстрый способ закупки.
- Высокая эффективность для повторных покупок и больших корзин.
- Хорошо ложится на B2B (количества, кратность, наличие).

### 4.9 Минусы

- Меньше “витринности” и вдохновения.
- Для новых товаров/категорий может потребоваться PDP чаще, чем в A/B.

## 5. Переключение A/B/C (требование к реализации)

Переключение должно быть простым и утилитарным:

- Desktop: небольшой “segmented control” в toolbar каталога: `A | B | C`.
- Mobile: кнопка “Режим” в sticky controls row, открывает sheet с выбором `A/B/C`.

Не делать: отдельные сложные настройки, “демо-режимы”, анимации.

## 6. Success criteria для этапа 1 (что измеряем)

- Time-to-first-add-to-cart из каталога.
- Add-to-cart rate на 100 просмотров.
- Количество действий до “перейти в корзину”.
- Доля фильтраций (использование фильтров) без роста отказов.
- Mobile usability: сколько пользователей добавили 3+ товаров без перехода в PDP.

## 7. Что сознательно не делаем на этапе 1

- Не делаем “премиальный” визуал.
- Не делаем сложные анимации и новые навигационные паттерны.
- Не переносим бизнес-логику во frontend.
- Не усложняем checkout и seller-контур ради каталога.
- Не строим “умные рекомендации” на первом шаге — только каркас мест под них.
